# Лабораторная работа №5

*Предсказание цен на недвижимость: анализ и сравнение моделей регрессии*
## Цель работы

Изучить процесс построения модели регрессии для предсказания стоимости домов, освоить основные метрики качества регрессионных моделей (MAE, MSE, RMSE), сравнить различные алгоритмы регрессии (линейная регрессия, случайный лес и т.д.), выполнить настройку гиперпараметров модели Random Forest, а также исследовать возможность интеграции обученной модели с веб-сервисом

---
## Ход выполнения работы

### 1. Загрузка и предобработка данных
Загружены данные с Kaggle о ценах на дома в округе Кинг (штат Вашингтон, США) за период с мая 2014 года по май 2015 года. Исходная выборка содержала 21613 наблюдений и 21 переменную. После разделения на обучающую и тестовую части были получены: обучающая выборка - 15129 наблюдений с 16 признаками, тестовая выборка - 6484 наблюдения с 16 признаками. Целевая переменная - `Целевая.Цена` (стоимость дома)

На этапе предобработки были проверены данные на наличие пропусков `методом info()`, после чего данные были разделены на входные признаки `training_points` и целевую переменную (`training_values`). Тестовая выборка состояла из 6484 наблюдений с аналогичной структурой

### 2. Обучение моделей
Обучены две модели из библиотеки scikit-learn:
- **Линейная регрессия (`LinearRegression`)** - базовая модель для установления линейных зависимостей
- **Случайный лес (`RandomForestRegressor`)** - ансамблевый метод на основе деревьев решений с параметрами по умолчанию

### 3. Оценка качества моделей
Оценка производилась на тестовой выборке с использованием метрик регрессии:
- **MAE (`Mean Absolute Error`)** - средняя абсолютная ошибка
- **MSE (`Mean Squared Error`)** - средняя квадратичная ошибка
- **RMSE (`Root Mean Squared Error`)** - корень из средней квадратичной ошибки

Результаты моделей:

Модель | MAE | RMSE
Линейная регрессия | 126852.51 | 201883.24
Случайный лес | 70995.76 | 136727.51

Случайный лес показал значительно лучшие результаты, что объясняется его способностью улавливать нелинейные зависимости между признаками

### 4. Исключение незначащих признаков
На основе анализа важности признаков из модели случайного леса были определены 5 наименее значимых признаков:
- Год реновации
- Количество этажей
- Спальни
- Состояние
- Площадь подвала

После удаления этих признаков качество моделей ожидаемо изменилось. Для линейной регрессии RMSE вырос на +0,9% (с 201883 до 203678), что говорит о том, что даже слабые признаки содержали некоторую полезную информацию. Случайный лес, напротив, показал улучшение - ошибка RMSE снизилась на 1,1% (с 136728 до 135282). Это подтверждает, что ансамблевые модели более устойчивы к удалению незначимых признаков. В данном же случае исключение зашумлённых переменных помогло модели снизить переобучение и незначительно повысить точность.

### 5. Настройка гиперпараметров Random Forest
Для улучшения качества модели случайного леса был проведён подбор гиперпараметров с помощью GridSearchCV с 5-кратной кросс-валидацией

Исследуемые параметры:
-` n_estimators` - количество деревьев в лесу
- `max_depth` - максимальная глубина деревьев
- `min_samples_split` - минимальное количество объектов для разбиения узла
- `min_samples_leaf` - минимальное количество объектов в листе

Лучшие найденные параметры:
- `max_depth=25` - ограничение глубины деревьев предотвращает переобучение, при этом сохраняя достаточную сложность для выявления нелинейных зависимостей
- `min_samples_leaf=1` - минимальное количество объектов в листе позволяет создавать точные правила для отдельных наблюдений
- `min_samples_split=2` - базовое значение, дающее деревьям достаточную гибкость
- `n_estimators=300` - увеличение количества деревьев повышает стабильность предсказаний

Результаты сравнения:
Модель | RMSE
Исходный случайный лес (параметры по умолчанию) | 136728
Оптимизированный случайный лес (GridSearchCV) | 135590
Изменение | +0,8% (улучшение)

Настройка гиперпараметров позволила незначительно улучшить качество модели: ошибка `RMSE` снизилась на `0,8%`. Лучшие параметры, найденные с помощью GridSearchCV: `max_depth=25`, `min_samples_leaf=1`, `min_samples_split=2`, `n_estimators=300`. Прирост качества оказался скромным и находится в пределах статистического шума, что говорит о том, что стандартные параметры Random Forest уже были достаточно близки к оптимальным для данного набора данных.

### 6. Исследование других моделей
В рамках самостоятельной работы была предпринята попытка построить модель, имеющую ошибку меньшую, чем у случайного леса. На основе статьи ["5 алгоритмов регрессии в машинном обучении, о которых вам следует знать"](https://habr.com/ru/companies/vk/articles/513842/) были рассмотрены следующие алгоритмы:
#### 1. Нейросетевая регрессия
**Применение:** задачи с очень большими объёмами данных (миллионы записей), компьютерное зрение, обработка естественного языка, когда важна максимальная точность, а интерпретируемость не требуется

**Преимущества:** улавливает сложные нелинейные зависимости, способна обучаться на больших объёмах данных, автоматически выделяет иерархические признаки

**Недостатки:** требует очень много данных для качественного обучения, склонна к переобучению без регуляризации, требует нормализации входных данных, трудно интерпретируема
#### 2. Дерево решений
**Применение:** задачи, где важна объяснимость предсказаний (медицина, скоринг), небольшие и средние датасеты, разведочный анализ данных

**Преимущества:** высокая интерпретируемость, не требует масштабирования признаков и нормализации, устойчиво к выбросам

**Недостатки:** сильно переобучается без ограничения глубины, нестабильно, низкая точность по сравнению с ансамблями
#### 3. Lasso (L1-регуляризация)
**Применение:** задачи с большим количеством признаков, где нужен автоматический отбор (геномика, тексты), когда важна интерпретируемость коэффициентов, подготовка данных для других моделей

**Преимущества:** автоматически отбирает наиболее важные признаки, обнуляя незначимые коэффициенты, создаёт разреженные модели, устойчива к мультиколлинеарности

**Недостатки:** работает только с линейными зависимостями, при сильной корреляции признаков выбирает только один из группы, не подходит для сложных нелинейных паттернов
#### 4. Ridge (L2-регуляризация)
**Применение:** задачи с множеством слабо влияющих признаков, когда нужно учесть все переменные, подготовка признаков для более сложных моделей

**Преимущества:** устойчива к мультиколлинеарности, более стабильна на зашумленных данных, сохраняет все признаки в модели

**Недостатки:** работает только с линейными зависимостями, не обнуляет признаки, что усложняет интерпретацию, не подходит для сложных нелинейных паттернов
#### 5. ElasticNet
**Применение:** задачи с большим количеством признаков и сильной корреляцией между ними, когда нужен и отбор признаков, и стабильность, финансовые и экономические данные с группами взаимосвязанных показателей

**Преимущества:** объединяет преимущества L1 и L2 регуляризации: автоматический отбор признаков, устойчивость к мультиколлинеарности, работает с группами коррелированных признаков

**Недостатки:** сложность настройки двух гиперпараметров (alpha и l1_ratio), требует больше времени для подбора параметров, при неудачном выборе параметров может работать хуже Lasso или Ridge по отдельности

Результаты моделей из статьи:
Модель | RMSE
Нейросетевая регрессия | 177295
Дерево решений | 200308
Lasso регрессия | 201853
Гребневая регрессия	| 201897
ElasticNet регрессия | 366002

*Ни одна из этих моделей не превзошла случайный лес (`RMSE = 136728`)*

Именно поэтому была выбрана и обучена модель `XGBoost` - градиентный бустинг, который по данным из статей часто показывает наилучшие результаты на структурированных табличных данных.
#### XGBoost
**Применение:** соревнования Kaggle (лидирует в задачах с табличными данными), продакшен-системы с требованием высокой точности, задачи кредитного скоринга и предсказания цен

**Преимущества:** высокая точность на табличных данных, устойчив к выбросам, контролирует переобучение через learning_rate и регуляризацию, оценивает важность признаков, высокая скорость обучения

**Недостатки:** требует тщательной настройки гиперпараметров, склонен к переобучению на малых данных, менее интерпретируем, чем случайный лес

**Параметры модели:**
```python
xgb_model = XGBRegressor(
    n_estimators=200,
    max_depth=6,
    learning_rate=0.05,
    random_state=42,
    eval_metric='rmse',
    verbose=False
)
```

**Сравнение результатов моделей XGBoost и Random Forest:**
Модель | RMSE
XGBoost | 125958
Random Forest | 136728
Изменение | +7.9%

Как и ожидалось, модель градиентного бустинга `XGBoost` работает лучше благодаря последовательному исправлению ошибок предыдущих деревьев. В отличие от случайного леса, где деревья строятся независимо и усредняются, XGBoost обучает деревья друг за другом, каждое новое дерево фокусируется на ошибках предыдущих, что позволяет достичь более высокой точности. Кроме того, XGBoost имеет встроенную регуляризацию, которая предотвращает переобучение, а также более эффективно работает с разреженными данными и позволяет настраивать скорость обучения `learning_rate` для более плавной сходимости.

### 7. Интеграция модели с веб-сервисом
Для внедрения обученной модели в реальный сервис по оценке недвижимости был исследован процесс интеграции с веб-фреймворками FastAPI/Flask/Django

Вот пошаговый алгоритм интеграции:
#### Шаг 1. Сохранение обученной модели
Сериализовать модель в файл с помощью `joblib.dump()` или `pickle`. Также сохранить объекты предобработки (например, `StandardScaler`), чтобы применить те же преобразования к новым данным
#### Шаг 2. Организация структуры проекта
Создать модульную структуру: отдельные папки для модели `/models`, схем валидации `/schemas` и эндпоинтов `/routers`
#### Шаг 3. Загрузка модели при старте приложения
Реализовать механизм глобальной загрузки модели при запуске сервера, чтобы модель хранилась в памяти и обрабатывала запросы без перезагрузки
#### Шаг 4. Валидация входных данных
Определить схемы (`Pydantic для FastAPI`) с указанием типов, обязательных полей и допустимых диапазонов значений для всех признаков недвижимости
#### Шаг 5. Реализация API-эндпоинтов
- `GET /health` - проверка работоспособности сервиса
- `POST /predict` - предсказание цены для одного объекта недвижимости
- `POST /batch_predict` - пакетная обработка нескольких объектов
#### Шаг 6. Обработка входных данных
Преобразовать входящий JSON в массив чисел в том же порядке, в котором модель обучалась. Применить сохранённый scaler (если данные масштабировались)
#### Шаг 7. Формирование ответа
Вернуть JSON с предсказанной ценой, статусом и (если надо) доверительным интервалом
#### Шаг 8. Обработка ошибок
Добавить try-except блоки, реализовать понятные сообщения об ошибках с соответствующими HTTP-статусами `400, 500`
#### Шаг 9. Контейнеризация (по желанию)
Создать Dockerfile и docker-compose.yml для воспроизводимости и упрощения деплоя
#### Шаг 10. Деплой и мониторинг
Развернуть сервис локально `uvicorn/gunicorn` или в облаке. Настроить логирование запросов и отслеживание дрейфа модели
