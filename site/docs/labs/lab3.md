# Лабораторная работа №3

*Перенос репозитория с GitHub на Yandex SourceCraft через SSH*
## Цель работы

Освоить процесс переноса Git-репозитория с платформы GitHub на платформу Yandex SourceCraft с использованием SSH-аутентификации, а также научиться настраивать локальный репозиторий для работы с несколькими удалёнными репозиториями одновременно.

---
## Ход выполнения работы

### 1. Генерация SSH-ключа
Так как на локальной машине отсутствовали SSH-ключи, была выполнена команда:
```bash
ssh-keygen -t ed25519 -C "моя почта"
```
Ключи сохранены в стандартной директории `~/.ssh/` (публичный ключ - `id_ed25519.pub`, приватный - `id_ed25519`)
### 2. Добавление публичного ключа на SourceCraft
Содержимое файла `id_ed25519.pub` было скопировано и добавлено в веб-интерфейсе SourceCraft в разделе `"Доступ" -> "SSH-ключи"` . Это необходимо для аутентификации при push-операциях
### 3. Добавление публичного ключа на GitHub
Для обеспечения доступа к GitHub по SSH публичный ключ был также добавлен в настройках аккаунта GitHub: `"Settings" -> "SSH and GPG keys"`. В поле `"Key"` вставлено содержимое файла `id_ed25519.pub`
### 4. Клонирование репозитория с GitHub
Репозиторий `anne4ka-rom.github.io` был клонирован на мой компьютер:
```bash
git clone git@github.com:Anne4ka-rom/anne4ka-rom.github.io.git
cd anne4ka-rom.github.io
```
После выполнения первой команды система запросила подтверждение подлинности хоста, т.к. это было первым подключением к GitHub через SSH, поэтому был введён ответ `yes`
### 5. Создание пустого репозитория на SourceCraft
На платформе SourceCraft был создан новый репозиторий с именем `"mkdocs-portfolio"`: `"Ваша мастерская" -> "Репозитории" -> "Новый репозиторий" -> "Пустой репозиторий"`. Репозиторий был создан без инициализации `README` и `.gitignore`, чтобы избежать конфликтов с уже существующей историей коммитов из GitHub
### 6. Привязка локального репозитория c GitHub к SourceCraft
Локально был изменён URL удалённого репозитория `origin` на адрес SourceCraft, который был получен в `созданном пустом репозитории -> правый верхний угол -> "Клонировать" -> скопировать ссылку SSH`:
```bash
git remote set-url origin ssh://ssh.sourcecraft.dev/annirom23/mkdocs-portfolio.git
```
### 7. Отправка кода на SourceCraft
Выполнена отправка всех веток и коммитов:
```bash
git push -u origin main
```

При первом подключении к SourceCraft также потребовалось подтвердить подлинность хоста ответом `yes`
### 8. Проверка результата
В веб-интерфейсе SourceCraft была проверена загрузка всех файлов, истории коммитов и веток - всё перенеслось корректно
### 9. Настройка одновременной отправки в два репозитория
Чтобы иметь возможность пушить изменения сразу и на GitHub, и на SourceCraft, был использован способ с несколькими push-URL для одного remote (GitHub остался основным репозиторием (источником для fetch и pull), но изменения отправляются сразу на обе платформы):
 Устанавливаем GitHub как основной remote (для fetch/pull)
```bash
git remote set-url origin git@github.com:Anne4ka-rom/anne4ka-rom.github.io.git
```
Добавляем SourceCraft как дополнительный URL для пуша
```bash
git remote set-url --add origin ssh://ssh.sourcecraft.dev/annirom23/mkdocs-portfolio.git
```
 После этого команда `git push origin main` отправляет изменения одновременно на обе платформы
