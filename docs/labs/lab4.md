# Лабораторная работа №4

*Предсказание дефолта по кредиту: анализ и сравнение моделей классификации*

## Цель работы

Изучить процесс построения модели классификации для предсказания дефолта по кредиту, освоить основные метрики качества (accuracy, confusion matrix, ROC-AUC), сравнить различные алгоритмы классификации (логистическая регрессия, случайный лес, XGBoost) и исследовать возможность интеграции обученной модели с веб-сервисом

---
## Ход выполнения работы

### 1. Загрузка и предобработка данных
Загружены данные с Kaggle соревнования. Обучающая выборка содержала 50 000 наблюдений с 10 признаками, характеризующими кредитную историю и социально-демографический профиль заёмщика. Целевая переменная SeriousDlqin2yrs (наличие просрочки более 90 дней за последние 2 года) показала сильный дисбаланс классов: только 6% клиентов имели дефолт
На этапе предобработки были заполнены пропуски в столбцах MonthlyIncome и NumberOfDependents средними значениями из обучающей выборки, после чего данные были разделены на входные признаки (training_points) и целевую переменную (training_values)
### 2. Обучение базовых моделей
Обучены две модели из библиотеки scikit-learn:
- логистическая регрессия
- случайный лес с параметром `n_estimators=100`
### 3. Оценка качества моделей
Оценка производилась на тестовой выборке из 37500 наблюдений с использованием метрик:
    **1. Accuracy:**
    - Логистическая регрессия показала accuracy, близкую предсказанию всех объектов как "не дефолт", что связано с дисбалансом классов
    - Случайный лес продемонстрировал более высокую точность, но данный показатель не является информативным для несбалансированных данных
    **2. Confusion matrix:**
    При анализе влияния порога классификации `0.3, 0.5, 0.7` были получены следующие закономерности:
    - Порог 0.3: увеличивается количество ложноположительных срабатываний `FP`, уменьшается количество ложноотрицательных `FN`
    - Порог 0.5: баланс по умолчанию
    - Порог 0.7: уменьшается количество `FP`, увеличивается количество `FN`
    В контексте предсказания дефолта по кредиту выбор порога является компромиссом между риском невозврата кредита `FN` и упущенной выгодой от отказа добросовестным клиентам `FP`
    **3. ROC-AUC:**
    - Логистическая регрессия: ~0.75
    - Случайный лес: ~0.85
### 4. Выбор и обучение альтернативной модели
В рамках самостоятельной работы была предпринята попытка построить модель, имеющую ошибку меньшую, чем в рассматриваемых в борде. Классические методы, такие как SVM и kNN, были отклонены на этапе анализа, т.к.:
- *kNN* имеет всего 10 признаков, чувствителен к выбросам, медленно работает на выборке из 50000 объектов, плохо справляется с несбалансированными классами
- *SVM* обладает низкой скоростью работы на данных большого размера, чувствительностью к шуму, нестабильной работой с несбалансированными классами
Вместо них была выбрана и обучена модель `XGBoost`
**Почему XGBoost подходит для этой задачи?:**
- *Адаптация к дисбалансу классов*
В обучающей выборке только 6% дефолтов, поэтому стандартные модели склонны игнорировать "редкий" класс. XGBoost позволяет задать параметр `scale_pos_weight=15`, который искусственно увеличивает важность миноритарного класса, заставляя модель обращать на него больше внимания при обучении
- *Устойчивость к особенностям данных*
Древовидная архитектура XGBoost не чувствительна к масштабу признаков и выбросам - в отличие от kNN и SVM, которые требуют нормализации и страдают от аномалий. Это особенно важно для таких признаков, как MonthlyIncome (от 0 до 3 млн) и DebtRatio
- *Глубина и количество деревьев*
Параметры `n_estimators=200` и `max_depth=6` позволяют модели находить сложные нелинейные зависимости, но при этом не запоминать шум
- *Контролируемое обучение*
Параметр `learning_rate=0.05` делает процесс обучения более плавным: каждое следующее дерево вносит небольшой вклад в исправление ошибок предыдущих. Это снижает риск переобучения и повышает обобщающую способность
Код реализации:
``` python
# установка модели
!pip install xgboost -q

from xgboost import XGBClassifier
from sklearn.metrics import roc_auc_score, classification_report

# создание модели с параметрами для несбалансированной выборки
xgb_model = XGBClassifier(
    n_estimators=200,
    max_depth=6,
    learning_rate=0.05,
    scale_pos_weight=15,
    random_state=42,
    eval_metric='auc',
    use_label_encoder=False
)

# обучение
xgb_model.fit(training_points, training_values)

# предсказание вероятностей
xgb_probabilities = xgb_model.predict_proba(test_points)[:, 1]

# ROC-AUC
xgb_roc_auc = roc_auc_score(test_values, xgb_probabilities)
print(f"XGBoost ROC-AUC: {xgb_roc_auc:.4f}")

# матрица сопряженности для разных порогов
from sklearn.metrics import confusion_matrix

for threshold in [0.3, 0.5, 0.7]:
    preds = xgb_probabilities > threshold
    tn, fp, fn, tp = confusion_matrix(test_values, preds).ravel()
    print(f"Порог {threshold}: TP={tp}, FP={fp}, FN={fn}, TN={tn}")
```

### 5. Анализ современных алгоритмов классификации
На основе анализа научных публикаций и решений Kaggle были выделены основные алгоритмы классификации:
    **1. Логистическая регрессия**
    **Применение:** базовая линейная модель для бинарной классификации. В соревнованиях Kaggle используется как простая и интерпретируемая модель. В одном из решений для оценки вероятности дефолта заёмщика модель, занявшая 1-е место, показала результат ROC AUC = 0,80570
    **Преимущества:** простота и интерпретируемость, быстрое обучение, не требует большого объёма данных, выдаёт калиброванные вероятности, устойчива к мультиколлинеарности при регуляризации
    **Недостатки:** не улавливает нелинейные зависимости между признаками
    **2. Метод K-ближайших соседей (KNN)**
    **Применение:** алгоритм классифицирует целевой объект на основе классов k объектов, максимально похожих на него. Используется в задачах с чёткими кластерами, например, в задаче Titanic для оценки выживаемости пассажиров
    **Преимущества:** отсутствие этапа обучения, простота реализации, естественная работа с многоклассовой классификацией, не делает предположений о распределении данных
    **Недостатки:** работает медленнее при увеличении объёма выборки и количества признаков, чувствителен к выбросам, требует определения оптимального значения k, плохо справляется с несбалансированными классами
    **3. Деревья решений**
    **Применение:** метод объединяет серию тестов, где числовая характеристика сравнивается с пороговым значением. Используется в задачах кредитного скоринга с настройкой параметров через GridSearchCV
    **Преимущества:** высокая интерпретируемость, не требуют масштабирования признаков, работают с пропусками, автоматически отбирают важные признаки
    **Недостатки:** базовые деревья склонны к переобучению. Для улучшения результатов применяют ансамблирование - обучение нескольких деревьев и усреднение их предсказаний
    **4. Метод опорных векторов (SVM)**
    **Применение:** алгоритм ищет разделяющую гиперплоскость, наилучшим образом разделяющую классы. Используется с мягким зазором `soft margin`, позволяющим нарушать условие правильной классификации с штрафом
    **Преимущества:** эффективен в высокоразмерных пространствах, работает с нелинейными разделяющими границами через ядра `kernel trick`, устойчив к переобучению при правильном выборе параметров
    **Недостатки:** низкая скорость работы на данных большого размера, чувствительность к шуму, нестабильная работа с сильно перекрывающимися классами
    ** 5. XGBoost (*выбран для итогового решения*)**
    **Применение:** доминирующий алгоритм на Kaggle для табличных данных. В задачах кредитного скоринга показывает лучшие результаты благодаря встроенной обработке дисбаланса классов и высокой обобщающей способности
    **Преимущества:** устойчивость к выбросам, интерпретируемость (важность признаков), масштабируемость
    **Недостатки:** требует тщательной настройки гиперпараметров, склонен к переобучению на малых данных, чувствителен к выбросам (меньше, чем SVM/kNN, но больше, чем случайный лес), ресурсоёмкий при обучении на больших данных, менее интерпретируем, чем логистическая регрессия или одно дерево решений
### 6. Интеграция модели с веб-сервисом
Для внедрения обученной модели в банковский процесс была исследована возможность интеграции с веб-фреймворками `FastAPI/Flask/Django`. Пошаговый алгоритм интеграции:
    **Шаг 1. Сохранение обученной модели**
    Сериализовать модель в файл с помощью joblib или pickle, сохранить метаданные (список признаков, версию, порог классификации)
    **Шаг 2. Организация структуры проекта**
    Создать модульную структуру: отдельные файлы для загрузки модели, валидации входных данных и эндпоинтов
    **Шаг 3. Загрузка модели при старте приложения**
    Реализовать механизм предзагрузки или "ленивой" загрузки (синглтон), чтобы модель хранилась в памяти и обрабатывала запросы без перезагрузки
    **Шаг 4. Валидация входных данных**
    Определить схемы (Pydantic для FastAPI) с указанием типов, обязательных полей и допустимых диапазонов значений
    **Шаг 5. Реализация эндпоинтов**

    **Шаг 6. Обработка ошибок**

    **Шаг 8. Деплой**
    Развернуть сервис локально (uvicorn/gunicorn) или в облаке (Cloud Run, AWS Lambda, Kubernetes)
    **Шаг 9. Мониторинг**
    Логировать запросы, отслеживать дрейф модели, при необходимости инициировать переобучение
