    Лабораторная работа №7¶

    Скрапинг и анализ текста

    Цель работы¶

    Освоение методов скрапинга данных из веб-страниц с использованием библиотек requests, BeautifulSoup и re. Получение навыков извлечения структурированной информации (идентификатор, заголовок, дата, просмотры, текст, теги) и сохранения результатов в формате CSV с соблюдением требований к структуре данных

    Ход выполнения работы¶

    В ходе выполнения работы был реализован парсер новостного портала . Работа разделена на несколько логических этапов:

    1. Настройка окружения и импорт библиотек¶

    В первой ячейке Colab были импортированы необходимые библиотеки, заданы домены для поиска и создана переменная для хранения собранных данных:

    import csv
import requests
from bs4 import BeautifulSoup
import os
import random
import time
import re

DOMAIN = 'https://news.itmo.ru'
SEARCH_DOMAIN = 'https://news.itmo.ru/ru/search/?search='
news_dict = {}
queries = ['нейротехнологии', 'нейротехнологии и программирование']

    2. Сбор общих данных по новостям (пункт 3 задания)¶

    Для поиска новостей по ключевым словам используется цикл по списку запросов. Для каждой страницы результатов:

    • Выполняется GET-запрос
    • Извлекается количество новостей из <div class="weeklyevents"> <h2> <span>
    • С помощью find_all('li', class_='weeklyevent') собираются заголовки и URL новостей
    • Данные сохраняются в словарь news_dict, где ключ - полный URL новости, а значение - заголовок
    for query in queries:
    data = requests.get(SEARCH_DOMAIN+query)
    bs = BeautifulSoup(data.text, 'html.parser')
    total_news = bs.find('div', {'class': 'weeklyevents'})
    news_headers = bs.find_all('li', {'class': 'weeklyevent'})
    for _n in news_headers:
        post = _n.find('h4').find('a').get_text()
        post_url = _n.find('h4').find('a').get('href')
        full_url = DOMAIN + post_url
        news_dict[full_url] = post

    3. Парсинг детальной информации по каждой новости (пункт 4 задания)¶

    Для каждого URL из news_dict выполняются следующие действия:

    3.1 Извлечение идентификатора новости¶

    С помощью регулярного выражения re.search(r'/(\d+)/?$', url) извлекается целочисленный ID из URL

    3.2 Дата размещения¶

    Поиск элемента <div class="time"><time>...</time></div>

    3.3 Количество просмотров¶

    Поиск <span class="icon eye"> и извлечение числа через регулярное выражение

    3.4 Текст новости¶

    Сначала ищется <div class="content js-mediator-article">, затем <div class="post-content">. Если они отсутствуют, то извлекаются первые 20 абзацев <p>

    3.5 Теги¶

    Поиск <div class="bulletin"> <ul class="tags"> <li> <a>. Теги склеиваются в строку через запятую

    3.6 Защита от блокировки¶

    Между запросами добавлена случайная задержка time.sleep(random.randint(1, 5)), а также обработка исключений try-except в цикле детального парсинга и при записи в CSV

    4. Сохранение данных в CSV¶

    Создаются два CSV-файла:

    • scraped_news_data_general.csv с общие данными: ID, название, дата, URL
    • news_content/news_details.csv с полные данными: ID, название, дата, просмотры, текст, теги, URL

    Перед записью создаётся папка news_content с помощью os.makedirs('news_content', exist_ok=True)

    Пример записи полных данных:

    Был реализован отдельный цикл для определения максимального номера страницы в разделе /ru/main_news/ путём анализа пагинации

    Нюансы при решении¶

    1. Особенности поиска элементов на странице - Вариативность вёрстки текста: Реализован поиск нескольких возможных контейнеров для текста новости (.content.js-mediator-article, .post-content), а также fallback на первые 20 абзацев - Извлечение ID из URL: Использовано регулярное выражение, устойчивое к слешам в конце строки - Поиск просмотров: Строка вида "123 просмотра" очищается от нецифровых символов с помощью re.search(r'(\d+)', views_text)

    2. Обработка ошибок и защита от блокировки - Реализована случайная задержка от 1 до 5 секунд между запросами для имитации поведения реального пользователя - Добавлены блоки try-except для обработки ошибок сети (requests.exceptions.RequestException) и ошибок парсинга - Пропущенные поля заполняются значениями по умолчанию ("Дата не найдена", "0", "У данной новости пока нет тегов"), что предотвращает остановку скрапинга из-за единичной ошибки

    3. Соответствие структуре данных Для каждого этапа сохранения определён строгий список fieldnames, что гарантирует одинаковый порядок и набор колонок в выходных CSV-файлах

    Результат¶

    В результате выполнения лабораторной работы был разработан скрапер, который:

    • Собрал общие данные о новостях (ID, название, дата, URL) по запросам "нейротехнологии" и "нейротехнологии и программирование"
    • Для каждой новости дополнительно извлёк количество просмотров, полный текст новости и теги
    • Сохранил результаты в два CSV-файла:
      • scraped_news_data_general.csv - общие данные
      • news_content/news_details.csv - расширенные данные с текстом и тегами

    Вывод¶

    В ходе выполнения лабораторной работы были успешно освоены основные методы веб-скрапинга с использованием библиотек requests и BeautifulSoup. На практике реализованы поиск и фильтрация HTML-элементов по тегам, классам и атрибутам, извлечение данных с вариативной вёрсткой (текст новости, теги), обработка пагинации и извлечение идентификатора из URL с помощью регулярных выражений. Особое внимание уделялось надёжности парсинга: все операции поиска элементов сопровождаются проверками на существование, что предотвращает падение программы при отсутствии того или иного элемента на странице.

    Реализована защита от блокировки с помощью случайных задержек между запросами и обработка HTTP-ошибок. Разработан механизм fallback для поиска текста новости в различных контейнерах, что позволяет корректно обрабатывать страницы с разной структурой вёрстки. Регулярные выражения позволили гибко извлекать числовые идентификаторы и количество просмотров из текстовых строк. Сохранение структурированных данных выполнено в формате CSV с разделением на общую (scraped_news_data_general.csv) и детальную (news_content/news_details.csv) части, что позволяет наглядно сравнить данные до обогащения (только метаинформация) и после (с текстом, просмотрами и тегами).

    Полученные навыки могут быть применимы в будущем для сбора и анализа новостных лент, мониторинга публикаций по ключевым словам и формирования наборов данных для последующего анализа, тематического моделирования и отслеживания динамики популярности новостей по просмотрам.
